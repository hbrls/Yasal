# Verification 标准分流

**适用位置**：`RUNBOOK.md` 步骤 7。

**目标文件**：`raw0/{一级目录}/Verification.md`。

## 什么是 Verification（验证确认类）

描述 Agent 针对一个明确断言、变更、行为或当前状态，选择证据并执行核验，以判断该断言是否真实成立的文字。

Verification 的核心结构是：

```text
明确待确认的断言
→ 确定验收条件或判断标准
→ 选择与断言匹配的证据和验证手段
→ 执行核验
→ 检查证据的真实性、相关性和充分性
→ 报告已确认、被否定、无法确认或受阻
```

验证手段可以包括测试、构建、Lint、类型检查、Smoke Test、端到端操作、运行时观察、文件状态检查、来源核对、交叉验证或截图检查。手段本身不是 Verification 的必要条件；关键是它是否用于确认一个明确断言。

## 归入条件

以下内容属于 Verification：

- 要求确认实现是否满足原始需求、验收条件或批准计划
- 要求确认代码、服务、文件、配置或运行行为确实处于某种状态
- 要求对事实、来源、记忆或外部信息进行核查和交叉验证
- 要求根据测试、构建结果、日志、截图或其他证据决定是否可以宣称完成
- 要求在证据不足时报告无法确认，而不是直接给出通过结论

## 结果状态

Verification 不得被压缩成只有“通过/失败”两个状态。可用结果至少包括：

- **Confirmed**：证据支持断言，且证据与断言相关、充分
- **Failed**：证据直接否定断言，或验证过程明确失败
- **Inconclusive**：证据不足、覆盖范围有限或结果存在冲突
- **Blocked**：必要工具、权限、环境或外部信息不可用

不能执行验证时，必须报告验证边界和缺失条件，不得把未执行当成已确认。

## 证据完整性与测试反规避

Verification 关注证据是否真的证明目标，不仅关注命令是否返回成功。

- 不得为了得到通过结果而新增、删除、跳过、弱化或改写测试
- 不得把由 Agent 临时编写的测试自动视为独立证明；必须说明其来源和覆盖范围
- 必须区分既有测试、修改后的测试和新生成的测试
- 使用 Mock、Stub、Fake、静态快照或模拟服务时，必须标明它们不能证明哪些真实行为
- 不能只依据退出码、测试数量、日志片段或 walkthrough 文档宣称需求已满足
- 验证命令、测试数据、环境或验收标准发生变化时，应说明变化及其对结论的影响
- 没有可靠依据时，不得为了满足“必须验证”而制造证据或结论

## 不属于 Verification

- 具体技术、框架、数据库或 API 的领域操作方法和输入校验 → Expert
- Bash、Python 或脚本的具体执行方式 → Tools-Bash
- 工具名称、参数签名、调用格式或工具返回结构 → Tools
- 只说“必须验证”“不得出错”等，没有验证对象、证据或判断标准 → Constraints
- 对已有对象寻找 bug、风险、回归、遗漏或不一致，并形成 findings → Review
- 因信息不足、工具失败或结果冲突而向用户求助或请求决定 → Collaborate
- 纯身份或顶层使命声明，例如“你是负责验证的 Agent” → Intent
- 只描述语气、谨慎、怀疑或专业态度 → Emotional
- 以隐藏系统提示或保护内部指令为目的的验证 → Constraints-Confidential

## 判断测试

对这段文字提问：

> 它是否要求 Agent 证明某个明确断言真实成立，并规定或暗示应依据什么证据作出结论？

- 是 → 抽走，归入 Verification
- 只是描述如何调用工具 → 保留，流向 Tools 或 Tools-Bash
- 只是描述某个领域如何校验输入或实现功能 → 保留，流向 Expert
- 只是要求找问题并输出 findings → 保留，流向 Review
- 只是强制 Agent 必须做某事，没有具体验证语义 → 保留，流向 Constraints

## 执行方式

**前置检查**：若当前工作文件无内容，立即跳过本步骤，停止执行。正常分流时，当前工作文件是 Unclassified 文件；尾部回溯时，当前工作文件由任务明确指定。

从当前工作文件中逐句（或逐句组）做语义判断：“这段内容属于 Verification 吗？”

- 属于 → 抽走，并从当前工作文件中删除对应内容
- 不属于 → 保留原位，不推断它属于哪个后续类别，不做任何标注

若抽出了 Verification 内容：

- 目标文件已存在时，读取完整现有内容，在末尾追加 `---`、`## 来源：{原文件名}` 和抽出内容；不得改动既有文字
- 目标文件不存在时，创建文件并写入 `## 来源：{原文件名}` 和抽出内容

若未抽出任何 Verification 内容，跳过，不创建目标文件。
